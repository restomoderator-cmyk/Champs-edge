# Приём анкеты на созвон

Сайт статический, поэтому анкету принимает отдельная функция в Yandex Cloud (регион `ru-central1`).
Порядок работы: заявка сначала записывается в Object Storage в России, и только потом копия уходит
в Telegram и на почту `edgechamps@gmail.com`. Если хранилище недоступно, заявка никуда не отправляется.

Секретов в репозитории нет и быть не должно. Функция читает их из переменных окружения,
значения лежат в Lockbox. В журнал функции попадает только номер заявки и состояние каналов.

## Что создать в консоли Yandex Cloud

1. Каталог в облаке, регион `ru-central1`.
2. Бакет Object Storage (закрытый, без публичного доступа). В нём появится папка `leads/`.
3. Сервисный аккаунт с ролями `storage.editor` (на бакет) и `lockbox.payloadViewer`. Для него статический ключ доступа.
4. Секрет в Lockbox с ключами из таблицы ниже.
5. Функция: среда выполнения Node.js 18 или новее, точка входа `index.handler`, таймаут 30 секунд, память 256 МБ.
   Загрузить файлы `index.js` и `package.json` из этого каталога (зависимости установятся при сборке).
   Привязать сервисный аккаунт и передать ключи секрета в переменные окружения.
6. API Gateway с одним путём, который передаёт `POST` и `OPTIONS` в функцию. Пример спецификации ниже.
7. Публичный адрес шлюза вписать в `FORM_ENDPOINT` в `js/main.js`. Это единственное, что попадает в код сайта.

## Переменные окружения (только имена)

| Имя | Откуда | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Lockbox | токен бота-уведомителя от @BotFather |
| `TELEGRAM_CHAT_ID` | Lockbox | числовой id чата, куда падают заявки |
| `SMTP_HOST`, `SMTP_PORT` | переменные | почтовый сервер для отправки, порт (по умолчанию 465) |
| `SMTP_USER`, `SMTP_PASSWORD` | Lockbox | учётная запись отправителя |
| `FROM_EMAIL` | переменная | адрес отправителя (если отличается от `SMTP_USER`) |
| `TO_EMAIL` | переменная | получатель, по умолчанию `edgechamps@gmail.com` |
| `S3_BUCKET` | переменная | имя бакета с заявками |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Lockbox | статический ключ сервисного аккаунта |
| `ALLOWED_ORIGINS` | переменная | разрешённые источники через запятую, по умолчанию `https://edgechamps.com` |

Бот должен получить от нужного аккаунта команду `/start`, иначе он не сможет написать первым.

## CORS

Функция сама отвечает на `OPTIONS` и ставит заголовки только для источников из `ALLOWED_ORIGINS`.
Запрос с другого сайта получает `403`. Зеркало на кириллическом домене перенаправляет на основной адрес,
отдельно разрешать его не нужно.

## Пример спецификации API Gateway

```yaml
openapi: 3.0.0
info: { title: ce-form, version: 1.0.0 }
paths:
  /lead:
    post:
      x-yc-apigateway-integration: { type: cloud_functions, function_id: <ID функции>, service_account_id: <ID сервисного аккаунта> }
    options:
      x-yc-apigateway-integration: { type: cloud_functions, function_id: <ID функции>, service_account_id: <ID сервисного аккаунта> }
```

## Контракт

Запрос: `POST`, `Content-Type: application/json`.

```json
{
  "id": "уникальный номер анкеты, его создаёт браузер",
  "name": "", "role": "player | agent | coach | club",
  "club": "", "league": "", "change": "", "contact": "",
  "consent": true, "website": "", "elapsed": 12000,
  "r": "ce_xxxxxxxx или пусто", "utm": { "utm_source": "" },
  "site_role": "", "site_path": "", "lang": "ru | en", "sport": "hockey | tennis", "url": ""
}
```

Ответ:

```json
{ "ok": true, "id": "...", "stored": true, "channels": { "telegram": true, "mail": false } }
```

- `ok: true` означает, что заявка сохранена и подтверждён хотя бы один канал. Только тогда сайт показывает
  «Заявку получили» и отправляет цель `form_submit_ok`.
- Если канал не ответил, функция пробует ещё раз. Повторная отправка анкеты с тем же `id` заявку не дублирует
  и досылает только в тот канал, который не подтвердился.
- `400`: не хватает обязательных полей или согласия. `403`: чужой источник. `502`: не удалось сохранить
  или не ответил ни один канал; сайт предлагает написать в Telegram или на почту.
- Заполненное поле-ловушка `website` или отправка быстрее трёх секунд: ответ `200` с пустыми каналами,
  ничего не сохраняется и не отправляется.

## Проверка

```
cd server/form-handler
node --test
```

Тесты работают без облака и без секретов: хранилище и каналы подменены.
Боевая отправка проверяется тестовой анкетой после настройки шлюза: заявка должна прийти и в Telegram, и на почту,
в обеих копиях видны код `r` и UTM.

Что пока не сделано: ограничение частоты запросов с одного адреса и капча. Если появится спам,
следующий шаг: Yandex SmartCaptcha.
